# Native port audit

Method: every catalogue course launched headless in release (`JUMPMAN_COURSE=<id> JUMPMAN_SCREENSHOT=... JUMPMAN_EXIT_AFTER=7`, Mario skin, audio off), logs grepped for panic/warn/error (none), screenshots read for black screens, missing geometry/actors, scale, sky/fog/water, HUD. Then every act (`JUMPMAN_ACT`) and every `warpSpawns` entry (`JUMPMAN_ENTRY`) of the Mario courses (147 runs, all clean), castle_inside areas 2 and 3, the 8 experiments, scripted playthroughs (teleport to the star -> dance -> iris wipe -> castle -> save dialog -> save; castle door; painting -> act selector -> course), and a frame-time pass (`JUMPMAN_FPS=1 JUMPMAN_NOVSYNC=1`).

## Defects found and fixed
| Defect | Root cause | Fix |
|--------|-----------|-----|
| After ANY course switch (star exit, door, painting, death warp to another course) Mario, the whole HUD, wipes and menus disappeared | `progress::tag_new` tagged every entity spawned between `mark_entities` and `tag_course_entities` as `CourseScoped`; unordered Startup systems (HUD, Mario view, camera, overlays, dialog UI, shell, audio, ...) landed in that window and were despawned by the first switch | `progress::PersistentSpawn` system set; all persistent Startup spawners are in it and `mark_entities` runs after it |
| Water surfaces vanished after a switch | spawned in Startup, tagged course-scoped, never rebuilt | `fx/water.rs` registers a `CourseRebuild` hook |
| Playground: star dance fires at the start (star sat on Mario's spawn and was ready immediately) | no `starLocations` entry, `requireCoins` not modelled | star at the TS position, gated on all meadow coins (`flow.rs`) |
| HUD title stayed on the previous course | the HUD swaps the curly apostrophe, the switch compared the raw name | compare normalised titles |

Test hooks added: `JUMPMAN_DEBUG_LOG=n` also logs `FLOW a -> b` transitions and the flow in the Mario line, `JUMPMAN_NOVSYNC=1`, `JUMPMAN_MSAA=off|2`.

## App-layer parity (moving platforms, colliders, goombas, cannons, doors, coins, signs)
`tests/rustFixtures.game.gen.test.ts` + `native/src/game/game_tests.rs` (see PORTING.md) replay the real TS world factory against the Rust app layer for 38 course/act/area runs x 2400 frames, seven bit-exact state hashes per frame. It found and fixed in Rust (full list in PORTING.md): three.js matrix math for platform collision, platform timer RNG order, collider sync timing and run-time colliders (chain chomp post), invincibility / coin pickup / loot coin order, goomba loot coin timing, cannon and buddy ordering and seat state, signpost floor snapping, the missing Jolly Roger Bay ship collision, missing castle entrance door and DDD warp wall colliders, wf implied collision models, JRB/DDD area-2 spawns, world freezing during door cutscenes. Not compared (presentation): particles, sfx, spark x/z jitter (own RNG).

### Second app-layer differential (`tests/rustFixtures.game2.gen.test.ts` + `native/src/game/game2_tests.rs`)
King Bob-omb dialog (ids 17/116/128, with the NpcDialogCamera eye/focus/return transition every frame), Koopa the Quick accept/decline, racing penguin accept/decline, the Wing Cap switch (collider squash, world surface hash, wing boxes), `CoinEffects` (number bounce, burst cadence, spark frames/scale), fading warps (bob pads) and in-place instant warps (castle_inside area 2): all bit-exact. Found and fixed in Rust: (1) `Math.hypot` vs libm `hypot` (and the 3-argument hypot in `polar`) in the camera, doors, paintings, fading-warp code -> `js_hypot`/`js_hypot3`; (2) NpcDialogCamera focus lerp used glam's rounding instead of three's `x += (v-x)*a`; (3) the king camera's return tail started one tick early and was dropped one tick late; (4) the racing penguin question skipped platforms/goombas/coin/invincibility steps (the whole tick was replaced) and Mario was stepped on the tick Koopa's invitation/result dialog opened (`Game.stepWorld` returns before Mario's step): both now live in `GameSim::tick_with` (`race_hold`), Koopa's top-of-tick question is `GameSim::koopa_question`; (5) a racer `answer` var was written every tick (extra object var); (6) fading warp ignored `ACT_TELEPORT_FADE_OUT` without an armed pad (TS falls through) and never snapped the camera behind Mario at the destination (`Progress::rig_snap`). Instant warps with an area change (ddd, wdw) and floor warps (jrb ship, totwc fall) are read-verified only.

## Audio parity (`tests/rustFixtures.audio.gen.test.ts` + `native/src/audio/audio_tests.rs`)
The real `Sfx.ts` runs in node against a fake worklet node that records every port message; the messages are turned into engine calls (`music-worklet.js` logic) and rendered through the same `sm64-us.wasm` in V8 at the engine's 32 kHz, commands applied between render blocks (`tests/audioScenes.json`: 7 scenes x 8 s - Bob-omb / Cool Cool / castle music with location changes, jump/land/coin/double+triple jump/footstep/star/red coin/secret/1up/bonk/ground pound/explosion sfx, underwater Jolly Roger Bay with swim/splash/water coin, metal cap + power music + cap switch, king/race/clear music events). The Rust `Sfx` + `Processor` (wasmi) plays the same scenes. Result (`cargo test -p jumpman audio_matches -- --nocapture`): the engine-call streams (name, arguments, render-frame stamp) are identical in every scene and the 32 kHz PCM is sample-for-sample identical (100.00%; RMS, Pearson correlation 1.000000, spectral cosine 1.000000 in all 7). So the Sfx port, `courses.json`/`sounds.json` lookups, terrain/metal/underwater offsets and the wasmi interpreter agree bit-for-bit with V8. Not covered: which gameplay events trigger which cue (the glue in `audio/mod.rs`, `progress/audio_glue.rs`; every `sfx.*` method `Game.ts` calls has a Rust call site) and the device-rate resampling. The render thread's stack was raised from 64 to 256 MB: a debug build of the interpreter overflowed 64 MB on the `sound_effect` scenes.

## Visual verification (headless screenshots, release build)
Checked by reading the PNGs: controls screen idle / listening ("PRESS A KEY...") / Esc-cancel (stays on the controls screen, binding unchanged: the cancelling key is swallowed from menu navigation) / rebind to K (Jump = K, the old K binding on Crouch is stolen); course result (`JUMPMAN_FLOW=result`) and act selector (`selector`) in the SM64 bitmap font; HUD (lives/coins/stars/title in the HUD font); secret/red-coin numbers (`JUMPMAN_FX_NUMBER=4`); the Zora's River water (`scrollT`: the water region changes between shots 0.5 s apart, the ground does not). New hooks: `JUMPMAN_SHELL_SCRIPT` accepts `rebind:<action>` and `key:Escape|Enter|Space|KeyJ|KeyK|KeyF` (real `KeyboardInput` events), `JUMPMAN_FX_NUMBER=<n>`. Defects found and fixed: the game-over card was invisible (the last Circle wipe frame, z 60, painted black over the card's text, z 50); the secret/red-coin number and spark models cast sun shadows onto the ground (in the web build only the player characters have `castShadow`).

## Performance
Release, 2080x1360 window, uncapped, shared machine (other jobs were using the GPU, so numbers are noisy): 11-19 ms/frame; the heaviest are the large SM64 outdoor levels (bob, castle_grounds, wf, bbh ~18.6 ms) versus 11-13 ms for small courses. Turning shadows off did not change bob; MSAA off gave ~14 ms in one noisy run, so cost is dominated by fill/MSAA at native resolution rather than CPU. No CPU hot spot was found; the 240p/480p render-target scaling in `PORTING.md` would be the lever if more headroom is wanted.
