# Porting Jumpman from Three.js/TypeScript to Rust

The Rust game lives in `native/`: `jumpman-sim` (no engine dependency, f64 like the TS original) and the Bevy app (`jumpman`) that renders it.

## Method
Every sim module is ported file-for-file from `src/sim/*.ts` and checked against **golden fixtures generated from the TypeScript** (`GEN_RUST_FIXTURES=1 pnpm vitest run tests/rustFixtures.gen.test.ts`, then `cargo test` in `native/`). Values must match bit-for-bit, not approximately.

## Bevy app architecture (`native/src`)
`main.rs` parses the course (`cargo run -- bob --act 2 --entry WARP_NODE_0A`, `--list`; env `JUMPMAN_COURSE/ACT/ENTRY`), builds a `GameSim` resource and adds plugins. Debug hooks: `JUMPMAN_EXIT_AFTER=<s>`, `JUMPMAN_SCREENSHOT=<png>`, `JUMPMAN_WALK=1`.

### App shell (`shell/`, `bevy_ui` in the `theme.css` look)
Files: `mod.rs` (state machine, events, course transition), `screens.rs` (title, pause, courses, settings, controls, save files, game over), `nav.rs` (keyboard/gamepad/mouse focus), `theme.rs` (palette, fonts, procedural star icon, buttons/panels), `settings.rs` (persisted JSON). Ports `Game.ts` glue, `index.html`, `theme.css`, `displaySettings.ts`.

`AppState` (resource, not `bevy_state`): `Boot -> Menu <-> Transition -> Playing <-> Paused`, plus `GameOver`. `SimSet` and `CameraSet` only run in `Playing`; Esc / pad Start pauses (Esc no longer quits; use the Quit button or Cmd+Q). A bare launch shows the title; a CLI course, `JUMPMAN_COURSE` or any headless hook (`JUMPMAN_EXIT_AFTER/SCREENSHOT/WALK`) skips straight to `Playing`. `JUMPMAN_SCREEN=title|pause|courses|settings|controls|slots|gameover|play` forces a screen, `JUMPMAN_SHELL_SCRIPT="course:bob@1,start@2,pause@8"` injects menu commands, `JUMPMAN_CONFIG_DIR` redirects `settings.json` (default `~/Library/Application Support/Jumpman/`).

Integration with the other modules: course changes go through `progress::Progress::pending` (so wipes, save and lives stay consistent): `StartCourse(CourseRequest)` fades out, queues a fresh-run `Switch`, waits for `progress` and fades in (other plugins may send it too; `progress::CourseSwitched` fires when the new `GameSim` is live). `SwitchCharacter` writes `characters::Character`; `OpenExperiment`/`LeaveExperiment` drive `experiments::ExperimentSlot` (unported experiments are dimmed; Esc now pauses instead of leaving an experiment, X still leaves); `ReturnToMenu` goes to the title (and leaves any experiment); `GameOver` shows the shell game-over screen (progress draws its own game-over overlay on the last life). The slot screen reads/writes `progress::save` (slot.txt, `SaveFile`, star counts) and a new file restarts the run. `settings::DisplaySettings` is persisted in `settings.json` and mirrored both ways into `fx::display::DisplaySettings` (env overrides win at launch; the native default is the modern preset); the shell itself only applies the 4:3 letterbox when aspect is classic. `SimSet`, `CameraSet` and the progress/experiment fixed-step hooks run only in `Playing` (`shell::is_playing`).

Fonts: drop `LilitaOne-Regular.ttf` / `Nunito-ExtraBold.ttf` into `assets/ui/fonts/` (the web build used Google Fonts); otherwise Arial Rounded (macOS/Windows) or Bevy's built-in font is used. Art in `assets/ui/` is converted from `src/ui/art/`. `package-mac.sh` bundles `assets/ui`, every course's models and the shared actors.

Shell gaps: touch controls, act selector / course-result / star dialogs (`ActSelector.ts`, `CourseResult.ts`), offline-save button, rebindable controls (the controls screen is a bindings reference), 240p/480p render-target scaling and filmic look (settings stored, not yet applied), save-file star counts (the save plugin must fill `SaveSlotSummaries`), game over is event-driven (the runner has no death/lives logic yet).

## Experiments (`native/src/experiments/`)
`X` opens the menu, `1`-`8` start one, `X`/`Esc` leaves; or `--experiment <id>` / `JUMPMAN_EXPERIMENT=<id>` (picks the experiment's course; the in-game menu relaunches the exe when the course differs). `Experiment` trait + `Host` (= `ExperimentHost`: `place_mario`, `set_mario_world`/`restore_mario_world`, `shift_mario`, `set_player_visible`, `add_coins`, `toast`, card/status text, `spawn` of XpEntity-tagged entities, `CameraOverride` pose) live in `mod.rs`; `StepControl` lets `before_step` replace the controller/camera yaw or skip the player step (hook in `sim_plugin::tick`). Test hook: `JUMPMAN_XP_KEYS="2.0:3,4.0:Tab"` presses keys inside the experiment.

Gotcha: SM64 orders a cell's floors by first-vertex height, so a sloped piece whose low corner is exactly at a floor's height loses the tie (God's ramp is lifted 2 units).

## Zelda content (`native/src/zelda/`)
`cargo run -- kokiri` (= `kokiri_forest`), `-- dungeon` (= `deku_tree`, `--area 2` is Gohma's lair), `-- shop`, `-- house` or any other course whose json has a `kokiri` block (`links_house`, `midos_house`, `graveyard`, ... all parse). Link is the default player there. Everything is inert on Mario courses.

* Zelda glbs have `sm64UnitsToMeters: 1` (authored in SM64 units): `zelda::glb::bevy_scale` gives the Bevy scale (0.01 vs 1 for SM64 exports); `render/course_view.rs` uses it for rooms and props. Managed objects (`CourseObject::{dungeon_role,treasure_key,speaker,rupee,fairy,idle,recovery_heart}`) are skipped by `LoadedCourse` and spawned/collided by `zelda`.
* Course changes (exits, warp pad, boss door) queue `progress::Progress::pending`; `ZeldaPlugin` rebuilds via `CourseRebuild` (all entities carry `CourseScoped`). The `ZeldaSave` resource is in memory (shared across switches in a run; persistence still to hook into `progress::save`).
* Keys: `H`/RB hold = aim slingshot (A fires), `T` equip/unequip, `Z`/`K` deflect nuts, Up/Down choose in menus. Test hooks: `JUMPMAN_ZELDA_FLAGS=sword,shield,slingshot,equipped,path,rupees=N,gohma,block,...`, `JUMPMAN_ZELDA_POS=x,y,z`, `JUMPMAN_ZELDA_PRESS=4:A,6:B`, `JUMPMAN_ZELDA_AIM=1`, `JUMPMAN_NO_TRAVEL=1`.
* Gaps: fixed-camera rooms (`links_house`, `kokiri_shop`, ...) draw the photograph as a plate and hide the room mesh, so the room no longer occludes actors (the ROM/TS keeps the depth); `scrollT` lava/water scrolling textures, `enclosed`/fixed sky variants, `spinZ` spinners, Navi ("fairy") is a bobbing model only, no pause-menu inventory (wallet text only), SFX for chests/dialogue/rupees beyond the coin cue, `mushroom2d`, `shipCollision`, linked areas, no Deku-nut/Gohma sounds.
